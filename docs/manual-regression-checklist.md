# TutorWEB 수동 점검 체크리스트

## 1) 휴회 요청/처리 플로우

### 1-1. 선생님이 휴회 요청 등록
- 경로: `/t/smain`
- 학생 선택 후 `휴회 요청` 버튼 클릭
- 입력:
  - 날짜(기본 오늘)
  - 대상(학생/학부모)
  - 상담내용
  - 목적: `휴회 요청`
- 저장

기대 결과
- 회차 카드(예정 수업/회차 목록/회차 상세)에 `휴회 요청` 배지 표시
- 상담 버튼 색상이 휴회 요청 톤(주황)으로 표시
- 학생 상태가 `휴회요청`으로 분류됨
- `/a/amain`의 `휴회 요청` 영역에 카드가 노출됨

---

### 1-2. 관리자가 휴회 취소 처리
- 경로: `/a/amain` → `휴회 요청` **카드 클릭** → `/a/smain` 이동 → 상담 기록의 `상담` 버튼
- 모달에서 입력:
  - 관리자 상담일
  - 최종상담
  - 상담결과: `휴회 취소`
- 저장

기대 결과
- 회차 배지가 `휴회 요청` → `휴회 취소`로 변경
- 학생 상태에서 `휴회요청` 해제
- 휴회 관련 숨김 처리 없음

---

### 1-3. 관리자가 휴회 확정 처리
- 경로: `/a/amain` → `휴회 요청` **카드 클릭** → `/a/smain` 이동 → 상담 기록의 `상담` 버튼
- 모달에서 입력:
  - 관리자 상담일
  - 최종상담
  - 상담결과: `휴회 확정`
  - 마지막 수업일
  - 환불 완료(선택)
- 저장

기대 결과
- 마지막 수업일 회차에 `마지막 수업` 배지(빨강)
- 휴회 관련 배지/상담 버튼 빨강 톤 반영
- 마지막 수업 이후 회차는 숨김 처리
- 학생 상태:
  - 오늘 <= 마지막 수업일: `휴회예정`
  - 오늘 > 마지막 수업일: `휴회생`
- 상담 기록 카드:
  - 환불 완료 미체크: `환불 예정` 배지(주황)
  - 환불 완료 체크: `환불 완료` 배지(빨강)

---

### 1-4. 휴회 확정 수정 반영(회귀 테스트)
- `/a/smain` 상담 기록에서 이미 `휴회 확정` 저장된 기록의 `상담` 버튼 클릭
- 마지막 수업일 변경 후 저장

기대 결과
- 변경된 마지막 수업일이 재오픈 모달에 그대로 보임
- 회차 숨김 기준/배지 위치가 새 날짜 기준으로 다시 반영됨

---

## 2) 연장 요청 + 결제 완료 + 결제일 재계산

### 2-1. 연장 요청(결제 미완료)
- 경로: `/a/smain` 또는 `/t/smain`
- `연장 요청` 버튼 클릭
- 목적: `연장 요청`, 결과: `연장`
- 결제 완료 체크 **해제**
- 저장

기대 결과
- 상담 기록에 `연장 요청` 배지
- 결제 기록(paymentHistory) 증가 없음
- 회차(planCount) 증가 없음

---

### 2-2. 연장 요청(결제 완료)
- 같은 모달에서 결제 완료 체크 후 저장
- 결제일, 추가회차 입력

기대 결과
- 결제 기록(paymentHistory)에 신규 레코드 생성
- 회차(planCount)가 추가회차만큼 증가
- 회차 카드 배지가 `연장 요청`이 아닌 `연장`으로 표시

---

### 2-3. 결제일 수정 시 재계산
- 방금 저장한 연장 상담 기록의 `상담` 버튼 클릭
- 결제일 변경(예: 2/5 → 2/3), 저장

기대 결과
- 연장 구간 회차 날짜가 **새 결제일 기준으로 재생성/재정렬**
- 마지막 회차 이후 결제일이면 결제일(또는 그 이후 첫 수업)부터 시작
- 기존 연결된 결제기록(paymentHistory)이 수정되고 중복 생성되지 않음

---

### 2-4. 연장 상담 삭제 시 정합성
- 연장 상담 기록에서 `삭제` 클릭

기대 결과
- 상담 기록 삭제
- 연동된 결제 기록(paymentHistory)도 함께 제거
- 증가했던 회차/표시가 원상 복구됨

---

## 3) 빠른 공통 확인
- `/a/smain`, `/t/smain`, `/s/smain` 권한별 버튼 노출 확인
- URL에 student/teacher token/id 직접 노출 없는지 확인(현재 선택 스토리지 기반 이동)
- 회차 상세/회차 목록/예정 수업 카드에서 상담 배지/상담 버튼 일관 표시 확인

---

## 4) KST 날짜 경계(자정/아침) 체크

### 4-1. 오전 수업 날짜 밀림 확인
- 학생 1명 생성
- 수업 시간을 `08:00` KST로 설정
- 수업일 당일에 접속

기대 결과
- 수업이 전날로 표시되지 않음
- 오늘 수업으로 정상 표시

---

### 4-2. D-day 정확도 확인
- 수업일 당일 접속

기대 결과
- D-day = 0(오늘) 표시

---

### 4-3. 자정 이후 상태 변화 확인
- 수업일 전날 23:30 KST 접속
- 다음날 오전 다시 접속

기대 결과
- 전날 23:30에는 아직 지나간 수업으로 계산되지 않음
- 다음날 오전에는 지나간 수업으로 정상 반영

---

### 4-4. 휴회 예정/휴회생 전환 확인
- 휴회 확정 기록 생성
- 마지막 수업일을 기준으로 당일/다음날 접속

기대 결과
- 마지막 수업일 당일: `휴회예정`
- 다음날: `휴회생`
