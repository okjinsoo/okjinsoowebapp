# 옥진수학 웹앱 기능 인벤토리 (2026-02-27)

이 문서는 "유료 전환 전 점검"을 위해 현재 프로젝트 기능을 한 번에 정리한 문서입니다.

## 1) 한 줄 요약

- 현재 앱은 `관리자(a) / 선생님(t) / 학생(s)` 3권한 구조로 동작합니다.
- 로그인은 Google만 사용합니다.
- 핵심 데이터(선생님/학생/회차/상담/강의)는 로컬 저장 + Supabase 공유 스냅샷 동기화 방식으로 운영됩니다.
- Google Calendar/Meet 연동은 회차 단위 자동 동기화 + 수동 재동기화 버튼까지 구현되어 있습니다.

## 2) 로그인/권한 기능

### 2-1. 로그인
- 홈(`/`)에서 Google 로그인만 지원
- OAuth 콜백(`/auth/callback`)에서 세션 저장
- 로그아웃 지원

### 2-2. 권한 분기
- 관리자: 고정 이메일 `rapah0310@gmail.com`
- 선생님/학생: Supabase `role_bindings` 기반
- `role_bindings` 지연 시 로컬 데이터(선생님/학생 이메일)로 1차 보강

### 2-3. 권한 라우팅 보호
- `/a/*`, `/t/*`, `/s/*` 경로 접근 제어
- 잘못된 권한 접근 시 홈으로 안내/리다이렉트

## 3) 관리자 기능 (a)

### 3-1. 관리자 메인(`/a/amain`)
- 학생/선생님 관리 이동
- 휴회 요청 학생 카드 확인
- `role_bindings 강제 동기화 실행` 버튼
  - 선생님/학생 이메일 권한 동기화
  - 공유 스냅샷 업로드

### 3-2. 학생 관리(`/a/students`)
- 학생 목록/검색
- 신규 등록/수정/삭제
- 상태별 섹션 분류(휴회/연장 등)

### 3-3. 선생님 관리(`/a/teachers`)
- 선생님 목록/신규/수정/삭제

## 4) 선생님 기능 (t)

### 4-1. 선생님 메인(`/t/tmain`)
- 담당 학생 목록
- 오늘 수업 카드
- 학생 상세/회차 이동

### 4-2. 학생 메인(`t/smain`)
- 학생 정보 카드
- 예정 수업 카드
- 수업 목록 이동
- 시간 변경, 일반 상담, 휴회 요청
- `회차 동기화` 버튼 (a/t만 표시)

## 5) 학생 기능 (s)

### 5-1. 학생 메인(`/s/smain`)
- 본인 정보/예정 수업/수업 목록
- 학생 권한에 맞는 읽기 전용/제한 UI

### 5-2. 학생에게 숨김 처리된 내부 필드
- `leafId`, `orderKey`, 필기 URL, 풀이 URL 등 내부 관리성 정보

## 6) 회차/출결/조정/상담 기능

### 6-1. 회차 구조
- 학생별 회차 생성/정렬/조회
- `displayAt` 기반 예정 수업 표시
- 회차 목록/회차 상세 페이지 제공

### 6-2. 출결/조정
- 출석/결석/조정 처리
- 조정 모달에서 변경일/시간, 이월, 사유/기록 저장
- 상태 배지 반영 (출석/결석/예정)

### 6-3. 시간표 변경
- 시작 날짜(또는 시작 회차) 기준으로 새 시간표 적용
- 변경 전 회차와 변경 후 회차 분리 적용
- 시간 변경 기록 조회/삭제

### 6-4. 상담/휴회/연장/환불
- 일반 상담, 연장 요청, 휴회 요청 기록
- 관리자 최종 처리(휴회 확정/취소)
- 환불 요청/환불 처리(기본/추가 결제 구간 반영)
- 학생 상태 계산(신규/진행/연장필요/휴회요청/휴회예정/휴회생 등)

## 7) 강의 저장소/회차 강의 기능

### 7-1. 강의 저장소(`/lib/lectures`, `/t/lectures`)
- 강의 목록 추가/수정/삭제/검색/순서 이동
- 단순 목록형(복잡 폴더 구조 제거)
- 강의 URL, 문제 URL 관리
- 자동 저장 + 공유 동기화

### 7-2. 회차 상세 강의 추가
- 저장소 목록을 불러와 회차에 강의 카드 배치
- 중복 추가 방지
- 선택 즉시 저장 반영

## 8) Google Calendar / Meet 연동

### 8-1. 기본 동작
- 회차 저장 시 자동 동기화 스케줄러 동작
- 이벤트 생성/수정/삭제
- Meet 링크 생성 및 회차 버튼으로 진입

### 8-2. 소유자 정책
- 회차 소유자는 "담당 선생님 이메일"
- 담당 선생님 계정으로 로그인해야 해당 회차 Meet 생성 확정
- 비소유자 로그인 시 pending 안내

### 8-3. 캘린더 선택
- `옥진수학` 전용 캘린더 우선 사용
- 없으면 자동 생성 시도
- 권한(scope) 부족 시 `primary` 캘린더로 폴백

### 8-4. 중복/이동 정리
- 같은 회차 중복 이벤트 탐지/정리
- 시간 변경 시 이전 슬롯 이벤트 정리 후 재생성
- 캘린더 이동(primary -> 옥진수학) 시 기존 캘린더 이벤트 정리
- 비대상 캘린더(primary 포함) 잔여 중복 정리 로직 포함

### 8-5. 수동 동기화
- `smain`에서 a/t만 `회차 동기화` 버튼 표시
- 동기화 결과 문구(성공/대기/오류 개수) 즉시 표시

## 9) 공유/동기화 구조

### 9-1. 로컬 저장
- 브라우저 저장소(`browserStorage`) 사용
- 오프라인/빠른 UI 반응 목적

### 9-2. Supabase 공유 스냅샷
- `app_state_snapshots`에 teachers/students/sessions/state_kv 업로드
- 다른 계정/브라우저에서 pull 후 hydrate
- 강의 트리/메타맵/상담 state_kv 동기화

### 9-3. role_bindings 자동 동기화
- 선생님/학생 이메일 변경 시 자동 upsert/delete
- JWT 만료 시 재시도 로직 반영

## 10) UI/디자인 공통 개선

- 라이트/다크 모드 표면색(`--surface-*`) 기반 정리
- 카드 hover 후 색상 복귀 문제 수정
- 배지 색상 통일
  - 성취도: `<=50 빨강`, `<=77 주황`, `<=90 파랑`, `<=100 초록`
  - 출석: 파랑, 결석: 빨강
- 주요 모달(조정/상담 등) 테마 정합성 보강

## 11) 현재 알려진 운영 제약

- 선생님 계정 토큰만으로 학생 캘린더에 "직접" 쓰는 것은 불가
  - 학생 캘린더 직접 생성/수정까지 하려면 서버 저장형 토큰 구조가 필요
- Google OAuth scope 설정 상태에 따라 전용 캘린더 생성이 제한될 수 있음

## 12) 유료 전환 전 최종 체크포인트

### 12-1. 필수 점검
- Google OAuth consent screen / scope / 테스트 사용자 설정 확인
- Supabase 환경변수/Redirect URL/Provider 설정 확인
- 회차 동기화 버튼 결과가 오류 없이 `synced`로 수렴하는지 확인
- `primary`와 `옥진수학` 중복 이벤트가 남지 않는지 확인

### 12-2. 유료 전환 시 바로 할 것
- Vercel Pro, Supabase Pro 업그레이드
- Spend Cap/비용 알림 설정
- 운영용 개인정보처리방침/이용약관/연락처 페이지 정리
